# Оформление статей раздела «История» (o-maps.spb.ru/history/)

Правила сложились при работе над `history/spb-history.html` («Ориентирование в Ленинграде и Петербурге», октябрь 2026). Применять к новым статьям и при правке старых. Образец, где всё это уже сделано, — `spb-history.html`.

## 1. Файлы и имена

- Статьи лежат в `history/`, папка — это рубрика. Неисторические статьи, если появятся, — в отдельных папках-рубриках, а не в общей `articles/`.
- Имя файла не должно совпадать с именем страницы в корне сайта (`spb.html`, `moscow.html`, `samara.html` — это карты). Региональные статьи: `history/<код региона>-history.html` (`spb-history.html`, `moscow-history.html`). Тематические: по теме (`woc.html`, `ussr-foot.html`). Страницы-оглавления рубрики: `domestic.html`, `iof.html`.
- Диаграммы и прочий JS статьи — `js/history-<код>.js`; в шапке файла — комментарий: для какой статьи, откуда данные, методика подсчёта (вплоть до явного списка id, если их нельзя отобрать по полю).
- Данные карты мест — `js/history-<код>-poi.js` (генерируется скриптами, см. § 7).
- Стили: сначала используем то, что уже есть в `main.css`, `theme.css` и Bootstrap. Новые правила для статей — в общий `css/history.css`, через токены `--o-*` из `theme.css` (светлая и тёмная темы без отдельных правил), а не в `<style>` на странице и не в отдельный файл статьи. Общие стили сайта (`main.css`, `theme.css`) меняем, только когда правка нужна и другим страницам (как тёмный вариант кнопки «↖»).
- В разметке допустимы лишь точечные `style`: `object-position` и `aspect-ratio` у картинок, `clear: both`, высота контейнера диаграммы.
- Общий JS: универсальные помощники — `js/utils-common.js` (`initTocHighlight`, `writeBackToStartButton`, `initReadingProgress`), логика сайта — `js/utils.js` (`initHistoryPlacesMap`).
- Новую статью прописать в трёх местах: меню «История» в `js/global-menu.js`, главная `index.html`, `sitemap.xml`.
- Переименование статьи — редирект 301 в `.htaccess` (раздел «Переименованные страницы») и правка всех трёх мест выше.
- `?v=` в подключениях JS и CSS не трогать.

## 2. Ссылки и окна

- В `<head>` — `<base target="_blank">`: по умолчанию всё открывается в новом окне, атрибут `target="_blank"` у ссылок не пишем.
- `target="_self"` — у ссылок на другие статьи `history/`, у кнопок «домой» и «календарь» в заголовке и у всех якорных ссылок (`#…`), иначе якорь откроется в новом окне.
- Внешним ссылкам — `rel="noopener"`, внутренним (`../…`) — не нужно.
- У каждого упомянутого сайта, издания, документа должна быть ссылка (SportIdent, SFR, «Азимут», O-Site и т. д.); Международная федерация ориентирования — всегда со ссылкой на orienteering.sport.
- Две ссылки не ставить вплотную через пробел — читаются как одна; развести словами («выиграла <a>классику</a> на <a>чемпионате…</a>»).
- Первичные документы (протоколы, программы, календари) — ссылкой на скан в `docs/ГГГГ/…_omaps.pdf`; скан, которого больше нигде нет в сети, сохраняется на сайте и регистрируется в `js/history-docs.js`.

## 3. Ссылки на данные сайта

Всё, что есть в данных O-Maps, связываем с его страницей — в тексте и в подписях к иллюстрациям:

| Что | Ссылка |
|---|---|
| событие календаря | `../event.html?id=SPB_19590719_1` |
| клуб, школа, другой POI | `../poi.html?poi=WN` |
| владелец-организатор | `../owner.html?owner=MILYA_SPORT` |
| соревнование (серия) | `../start.html?start=WN` |
| карта | `../map-info.html?map=roschino_1971_wn` |
| карты автора | `../sheet-all.html?author=SHRNN` |
| календарь целиком | `../calendar.html?startYear=ALL` |

- Каждый id перед отправкой проверить на существование (скриптом по `js/calendar-*.js`, `poi.js`, `owners.js`, `starts.js`, картам).
- Ссылка на событие должна вести на то самое событие: год, место и название совпадают с текстом (а у картинки-ссылки — с подписью).
- Если в статье упоминается старт, которого нет в календаре, его добавляют в календарь (с известной информацией и ссылками), а не оставляют без ссылки. Без точной даты в календарь не добавляем — тогда без ссылки.
- Подпись к карте заканчивается ссылкой «Страница с оригиналом карты ↗» на `map-info.html?map=…` (не на файл-оригинал); стрелка ↗ означает «откроется в новом окне». После неё — значок 📍 (§ 7).

## 4. Ссылки на людей

- Источники страницы о человеке, по приоритету: страница на нашем сайте (`volkov_av.html`, `tokma.html`) → личная страница O-Site (`o-site.spb.ru/history/Peoples/…`) → поле `about` в `js/authors.js` → материал в «Азимуте», o-moscow.ru, spbof.ru → «Список 280» на O-Site.
- В `authors.js` поле `about` может быть относительным (`'volkov_av.html'`): его выводят только страницы из корня сайта.
- **В каждом разделе** первое упоминание человека — обычная ссылка; повторные упоминания — «тихие» ссылки `class="hist-quiet"` (цвет текста, пунктирное подчёркивание, зелёные при наведении).
- **Каждая подпись к иллюстрации считается отдельно** от текста раздела: первое упоминание в подписи — тоже обычная ссылка.
- Ссылка охватывает имя целиком: «Людвиг Викторович Беляков», а не только фамилию.
- Не ставить ссылку на людей в кредитах иллюстраций («Фото из книги Н. В. Благово» — рядом уже ссылка на книгу) и в разделе «Источники».
- В блоке фактов людей можно связывать ссылками; ссылка там тихая (`hist-quiet`), чтобы не перегружать справку и не забирать «первое упоминание» у текста раздела.
- Тёзок проверять по годам и контексту (юниор 2003 года С. Кузнецов ≠ С. В. Кузнецов 1954 г. р.; А. М. Волков ≠ А. В. Волков; А. А. Курдюмов-старший (1945–2008, страница akurd-sr.html) ≠ А. А. Курдюмов-младший, 1969 г. р., разработчик SFR и президент ФСО СПб 2007–2013 — только «Список 280»). При сомнении — без ссылки.
- Спортсменов, которые несовершеннолетние сейчас (на момент составления статьи), по именам не называть — «юные петербуржцы». Тех, кто выступал в юношеских и юниорских стартах в прошлом и давно вырос, называть можно. Взрослых чемпионов страны и призёров взрослых международных стартов называть можно; спортсмен без страницы о нём — жирным, без ссылки.

## 5. Структура страницы

1. Заголовок с кнопками «домой» и «календарь».
2. `hist-nav` — навигация по статьям рубрики.
3. Вводный раздел `#intro`: 2–3 абзаца, «на что опирается статья» (источники со ссылками), фраза-ссылка на указатель имён; блок фактов `<dl class="hist-facts">` (в нём числа O-Maps — с датой, § 9); лента `hist-timeline`.
4. Оглавление `nav.hist-toc` (§ 6).
5. «Места на карте» `#places` (§ 7) — если в статье есть места.
6. Разделы `<section class="hist-section clearfix" id="…">` с `<h2>`; хронологические — с годами в заголовке («1966–1970: …»), затем тематические (виды, тренеры, руководители). Внутри раздела можно дать врезку `<dl class="hist-facts">` (например, счёт серий матчей).
7. «Вместо заключения» `#afterword`: что происходит сейчас и куда всё движется — по фактам, без оценочных преувеличений.
8. `hist-more`: «Статья составлена в <месяц год>. Это компиляция материалов O-Maps и других источников…, при её подготовке использовался ИИ» + «напишите нам».
9. «Источники» `#sources` (`<small>`, все со ссылками), с датой актуальности чисел O-Maps.
10. «Указатель имён» `#names` (§ 8).
11. `hist-more` «Посмотреть архив: …» и `hist-nav` — ссылки на предыдущую и следующую статьи.
12. Кнопка «наверх» и полоса прогресса чтения (§ 6).

## 6. Навигация

- У каждого раздела — осмысленный `id` (`#1959`, `#matches`, `#2010s`); его не менять — на него ссылаются оглавление, указатель и карта мест. CSS даёт `scroll-margin-top`.
- **Оглавление** `<nav class="hist-toc" aria-label="Оглавление статьи"><p class="hist-toc-title">Оглавление</p><ol><li><a href="#id" target="_self" title="полный заголовок раздела">короткое название</a></li>…` — после вводного раздела. На экране ≥ 1500 px оно уходит в левое поле и «прилипает»; текущий раздел подсвечивается: `<script>initTocHighlight();</script>`.
- **Кнопка «наверх» и полоса прогресса** — в каждой статье (не на страницах-оглавлениях `domestic.html`, `iof.html`), перед подключением `welcome.js`:
  ```html
  <div id="page-start"></div><button id="back-to-start" type="button" aria-label="К началу страницы">↖</button>
  <script>writeBackToStartButton({smooth: true}); initReadingProgress();</script>
  ```
  Кнопка общая с календарём (стили в `main.css`/`theme.css`, есть тёмный вариант); полоса — `.hist-progress` в `history.css`.

## 7. Карта мест

- Раздел `#places` после оглавления: карта Leaflet (`#places-map`), легенда по эпохам, список «Все места списком». В блоке фактов «Главные районы» — ссылка на `#places`.
- Точки — те же, что у событий на карте календаря: координаты события или центр его карты (у многодневок точек несколько); ссылка статьи на карту — центр этой карты. Близкие точки не объединяются, их склеивает кластеризация. Цвет точки — эпоха первого упоминания места в статье.
- На точку накладывается карта из каталога O-Maps — только та, что содержит точку (своя карта события, иначе выбранная вручную). Масштаб колесом мыши и двумя пальцами включён.
- **Значки 📍** (`a.hist-place-pin`, ведут на `#place-<точка>`) — после **каждого** упоминания места: ссылки на событие или карту в тексте раздела. Упоминания в иллюстрации (картинка-ссылка и ссылки в подписи) дают один значок на место в конце подписи, перед `hist-credit`, через `&nbsp;`. В блоке фактов и в ленте вех значков нет. id значка — `pl-<точка>-<раздел>`, у повторов в разделе `-2`, `-3`… В попапе точки «В статье:» — по одной ссылке на раздел.
- Данные и значки строятся скриптами (вне репозитория): `inventory.js` (ссылки статьи) → `build_points.py` (`js/history-<код>-poi.js`, отчёт о присоединении событий по названию места и исключения) → `apply_places_html.py` (раздел, значки, подключение). Скрипты идемпотентны; после правки текста значки снимаются и ставятся заново.
- Вызов: `<script src="../js/history-<код>-poi.js"></script><script>initHistoryPlacesMap(<данные>);</script>`.

## 8. Указатель имён

- В конце статьи, свёрнут: `<section id="names"><details id="names-details" class="hist-names"><summary><h2>Указатель имён</h2></summary>…`. Небольшой inline-скрипт раскрывает его при переходе по `#names`.
- Одна колонка, по алфавиту (ё = е). Строка: **Фамилия Имя** (ссылка на основную страницу) · другие источники · надстрочные цифры — места упоминаний.
- Отчество — только если найдено полностью в источнике («Список 280», список почётных членов ФСО СПб, заголовок страницы O-Site), и только во всплывающей подсказке (`title`), чтобы строки были единообразны. Девичья фамилия — в скобках в самом имени: «Казанцева (Малова) Ольга».
- Дополнительные источники — не больше 10 ссылок на человека всего; порядок: другие страницы O-Site и статьи самого человека → «Азимут» → мемориалы на O-Maps (`start.html`) → «карты на O-Maps» (`sheet-all.html?author=…`) → «Список 280» → почётные члены ФСО СПб → руководители ФСО СПб. Только ссылки, проверенные на то, что они про этого человека.
- Места упоминаний: у ссылки в тексте `id="nmK-N"` (N — по порядку в документе); в указателе `<a href="#nmK-N" target="_self" title="Название раздела (подпись к иллюстрации)">N</a>`. В CSS: `scroll-margin-top`, подсветка `:target`.
- После правки текста номера N и цифры указателя пересобираются скриптом; новый человек — новая строка указателя.

## 9. Текст

- Каждый факт, дата, число — из источника; ничего не додумывать (отчества по инициалам, даты «примерно», «первый в стране», если источник говорит «первый в городе»). Если источники расходятся — сказать об этом в тексте («по летописи — 1978 год, по книге Благово — 1983-й»).
- Цитаты — с указанием автора и ссылкой на публикацию (проверить, что цитата действительно там: перепечатка в книге и первая публикация — разные места).
- Статистика (числа событий, карт, медалей) — считается скриптом по данным сайта, методика описана в подписи к диаграмме и в шапке JS; при изменении данных — пересчитать.
- Числа O-Maps устаревают: в блоке фактов — «(на <месяц год>; все числа O-Maps — на эту дату)» со ссылкой на `#sources`, в «Источниках» — «числа о картах и событиях O-Maps в тексте и на диаграммах — по состоянию на <месяц год>, архив и календарь продолжают пополняться».
- Первое предложение раздела не повторяет слова заголовка.
- Не путать сходные понятия (маркированная трасса vs маркировка со штрафными кругами) — формулировать так, чтобы не было кажущихся противоречий.
- Неразрывные пробелы ставит скрипт-типограф (`nbsp_typograph.py`, вне репозитория; идемпотентен, `-n` — пробный прогон): в инициалах («Н.&nbsp;В.&nbsp;Благово»), между числом и словом, в «5&nbsp;000», после «№», перед тире. Прогонять после каждой правки текста.

## 10. Иллюстрации и диаграммы

- `<figure class="hist-fig hist-fig-right|left|none [hist-fig-narrow]">` + `<figcaption>`; вертикальные фото — `hist-fig-narrow`; портреты рядом — сетка `hist-heroes`, кадрирование — `object-position`.
- В подписи: что изображено, когда, где, кто (со ссылками на людей, события, карты); в конце — `<span class="hist-credit">Фото: …</span>` с источником.
- `alt` обязателен и содержателен; ссылки внутри `alt` невозможны — не дублировать в нём разметку. У `<img>` — `width`/`height` и `loading="lazy"`.
- Картинка-портрет может быть ссылкой на страницу человека (личную, а не на оглавление вроде Peoples/peoples.html); картинка-карта — на `map-info.html`; картинка-событие — на то же событие, что в подписи.
- Диаграммы — Chart.js в `<figure class="hist-fig hist-fig-none">` с контейнером фиксированной высоты; цвета — из токенов темы (перерисовка при смене темы); под каждой — свёрнутая «Таблица с данными» (в блоке с горизонтальной прокруткой). У горизонтальных диаграмм на узкой ширине длинные подписи сокращаются («А. Василевский»).

## 11. Мобильная вёрстка (360–400 px)

- Страница не должна прокручиваться вбок. В `history.css` для ширины ≤ 600 px: заголовок шапки переносится и мельче, лента вех — в две колонки с переносом подписей, ссылки в указателе имён переносятся целиком (`inline-block`). До 700 px иллюстрации — на всю ширину.
- Проверять скриптом (нет элементов правее края, кроме содержимого блоков с прокруткой) и глазами — скриншоты всей страницы на 360 и 400 px.

## 12. Данные

- Аномалии в данных (неизвестные коды стартов, расхождения дат, пустые места) — сообщать списком для ручной правки, не исправлять эвристически.
- Карта события может быть датирована позже события — она задаёт район, это не аномалия.
- Id событий не менять никогда.
- Для региональной статистики: события календарей региона + записи `calendar-fsor.js`, `calendar-iof.js`, `calendar-irf.js` с `region: '<КОД>'` и их дочерние записи; события региона из общих файлов без поля `region` (например, `calendar-common.js`) — явным списком id в шапке JS.

## 13. Проверка перед отправкой

- Playwright на `python3 -m http.server 8765` (на 1600 и 390 px): нет JS-ошибок, диаграммы и карта мест отрисованы.
- Нет вложенных `<a>`, нет дублей `id`, нет битых `#якорей`, у всех якорных ссылок `target="_self"`; нет двух ссылок вплотную.
- Все id событий, POI, карт, стартов существуют.
- Текст статьи (без тегов, без значков 📍) не изменился, кроме задуманных правок — сравнить по разделам с предыдущей версией.
- Мобильная ширина 360–400 px (§ 11).
- Перед публикацией новой статьи — независимая проверка фактов отдельными агентами по группам разделов (и отдельно — числа и диаграммы): таблица расхождений по категориям (ошибки, ссылки не о том, неточные формулировки, числа, расхождения источников, не удалось проверить, аномалии данных); правки — после решения автора.
